# Harness v0 (seed)

- Before declaring the task done, re-read the task's literal requirements and verify your output satisfies each stated requirement exactly as worded — a self-check that validates your own interpretation is not verification.
- If you cannot verify a requirement, say so explicitly rather than claiming success; never present partial or unverified work as complete.

- When the acceptance contract specifies behaviors the artifact must exhibit under a condition (e.g. what must still happen during teardown), build a separate check for EACH specified behavior variant taken from the contract's wording—not one convenient case—before declaring done; a single green self-test covering one shape is insufficient.
