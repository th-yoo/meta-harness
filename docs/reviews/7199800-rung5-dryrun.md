For a reader with no context: this branch is a zero-spend screening probe. Before anyone builds a rung-5 benchmark arm around the idea that "the harness divides a G-code fixture's embossed text into per-glyph images and the agent conquers one glyph at a time", it renders those glyphs locally and asks whether they are legible at all — because if the harness can divide perfectly and the glyphs still cannot be read, the arm is dead before it is built. It ships one developer tool, `term-bench2/seam-gate/render_glyphs.py`, its tests at `term-bench2/seam-gate/test/test_render_glyphs.py`, and a written verdict plus artifacts under `docs/loop-probes/rung5-dryrun-20260819/`. The tool is numpy+cv2 while the rest of `seam-gate/` is stdlib-only because it runs inside a task container; `sync-task-copies.sh` is a four-file allowlist (`validator`, `spec_check`, `hook`, `readers`), so this tool cannot reach the container, and nothing imports it. One constraint shaped all seven rounds of this review and belongs in the permanent record: Bash was disabled in my session, so I executed nothing — no test suite, no gate-check, no interpreter, no git command. Nothing in this document certifies "191/191" or "gate-check exit 0"; those remain the author's measurements. Everything below was established by reading the tree and recomputing numbers by hand from committed artifacts. I also could not detect uncommitted edits, and the working tree did move under me once mid-review, so this review is of the commits named above as they read on disk.

What I verified by recomputation rather than by trusting the text: the pipeline figures in `report.txt` (38972 S0 extruding points, 31 connected components at the calibrated cell 0.4 — inside the shipped spec's [25,38] — and 26 glyphs after a parameter-free u-overlap merge); fragility 0.63/8.895 = 0.071; coverage 133.58/168.16 = 0.794; median aspect 0.6615; width_ratio 8.25/5.70 = 1.45; pitch_ratio 5.70/1.46 = 3.90. Every synthetic in the limits table reproduces: shattered coverage 30/88 = 0.341, aspect 1.0/9 = 0.11, fragility 2.0/9 = 0.222 against healthy 0.513/9 = 0.057; fused coverage 1.000, fragility 5/9 = 0.556, aspect 35/9 = 3.89; partial-fusion width_ratio 15.1/5.7 = 2.65 and coverage 55.0/59.2 = 0.929. The uniform-fusion row reproduces to three figures from the fixture's own gap list — thirteen bridged gaps summing 17.03 give coverage 0.8956, the thirteen fused aspects have median 1.38, and the thirteen fused widths give 15.40/12.48 = 1.23. I read the committed images too: `whole.png` renders upright and unmirrored, and `contact-sheet.png` carries 26 index-labelled tiles at a common scale, with tiles 10 and 13 thin dashes and tile 7 an ambiguous oval — matching the verdict's own downgrade from 26 legible glyphs to 23-24.

The last outstanding finding is closed. The `TestLimitsTableIsNotStale` class docstring had described the implementation that the same commit replaced, claiming a single-occurrence edit could not fail the check while the two method docstrings twenty lines below recorded the opposite; both paragraphs claimed provenance from mutation testing and they could not both be right. It now states only what the three re-run mutations support — editing the closing line's value alone fails, removing a figure wholesale from either copy fails, the unmutated tree passes — and keeps the honest residual, that it verifies both copies carry the current value under its own label and not that a figure sits in the correct row. That was the right way to close a provenance claim: re-run the measurement rather than edit the prose to match.

The history is the durable part, because the same defect class recurred six times and the account of it is worth more than the tool. Three versions of `separation_margin` shipped a check that could not report the condition it was named for: a `separated` boolean whose comparison was true by construction, a fragility metric normalized by median glyph width that scored a shattered divide 23x safer than a correct one, and a max-form aspect detector that read 413 on the real fixture and false-alarmed because two underscore glyphs are legitimately 6.04 wide by 0.01 tall. A fourth appeared in the tests: the regression assertion guarding the second fix was transposed, reading `healthy < shattered * 20`, so it passed on the very inversion it named. A fifth appeared in the commit that removed the fourth: a filter over glyph spans that are disjoint by construction, justified by a comment claiming it differed from the already-computed `inter` list when the two are identical element-for-element. A sixth appeared inside the anti-staleness check itself, where `assertIn("26")` was satisfied forever by the verdict's own "2026-08-19" dateline. Separately, two claimed measurements did not reproduce: a numpy-2 `.ptp()` fix reported as complete while the method form survived in the render loop, and a width_ratio of 1.99 that is 2.28 once the fused glyph is bridged in place rather than moved — the latter retracted in the verdict rather than silently corrected.

What is clean at this sha. The instrument's arithmetic, guards and triggers: four advisory triggers living in named constants, pinned by value in the suite so lowering one to make a known case fire turns the suite red, none affecting the exit code, each described as chosen to sit between two measured artifacts rather than as arbitrary or calibrated. The limits table, which is the deliverable's load-bearing artifact: every row marked `[synth]` or `[real]` so no one compares a run against a baseline from the other world, a "moves only" column kept distinct from "REPORTS it" so no statistic is credited with reporting a failure it merely responds to, and a "blind / WRONG" column that names coverage maxing at 1.000 on global fusion and fragility still reading 0.222 against 0.057 on shattering. Both hand-maintained copies carry all seven closing figures, and a doc-test now fails if either drifts. Portability: `np.ptp` and an explicit 2D cross product throughout, so the tool runs under numpy 1.26.4 and the repo's own 2.5.1. Every `MergeMargins` consumer reads the right field, and the empty-components path returns NaNs by keyword instead of raising.

Limitations that must not be lost, all stated in the verdict and none of them closed by it. This is a screening test, and screening tests carry information when they fail; this one did not fail, so the honest status is "rung-5 is not eliminated", never "rung-5 is worth building". The 26-glyph count agrees with an answer that was already known. The tile-level legibility judgement was made by a reader who knew the target string, and the document labels that contamination rather than hiding it. The delivery-channel question — whether the arm's haiku-tier agent physically receives an image it can see — is argued but unmeasured, and must precede any build spend; a transport error there must be treated as a transport failure and never as evidence the tier cannot see the glyph. And the detectors catch non-uniform deformation only: a slightly-too-large cell that fuses every glyph with a neighbour leaves 13 glyphs of 26 while width_ratio reads 1.23, median aspect 1.38 and coverage 0.896 — better than the correct partition. `pitch_ratio` moves diagnostically there, 3.90 to 8.30, but only 5.00 in the adversarial variant, so it deliberately ships with no trigger, since any cutoff between 3.90 and 5.00 would be fitted to the two artifacts in hand. Closing that case needs an independently-derived partition — stroke or file-order contiguity compared against the u-overlap one — not another aggregate.

Two process observations worth keeping. First, the strongest findings in this review came from reading the artifact instead of the report: the numpy-2 failure was inferred from which three values were quoted as proof (all printed before the surviving `.ptp()` call, so the evidence was equally consistent with an AttributeError immediately after the last quoted line), and the 1.99 was caught by refusing to doubt arithmetic that reproduced everywhere else in the same file. Six times across seven rounds an author's description of a change did not match what the change did — including a patch script whose `str.replace` silently returned the original on no match, which made three rounds of "fixed" into three no-ops. Second, and recorded because it nearly invalidated a mutation test: overwriting a Python source with a same-byte-length variant does not invalidate `__pycache__`, so a "restored" run can report the mutated result while the file on disk is correct. Mutation testing Python sources needs `python3 -B` or an explicit cache purge, or it measures the cache.

I approve. The instrument does what the verdict says it does, every number I can re-derive reproduces, the container separation holds, the tests pin behaviour rather than restating it, and the written verdict is the most carefully scoped artifact I have reviewed in this repository — it retracts its own errors by name, marks its own contamination, and states the failure modes its detectors cannot see. Seven rounds is not a sign the branch was weak; it is a sign that each round's fix was inspected as adversarially as the original, which is how the fifth and sixth instances of the defect class were found at all. The one thing a future reader should carry away is the branch's own transferable lesson, arrived at the hard way: every one of these broken checks was a statistic computed from the very partition it was scoring, and a quantity derived downstream of the decision under test cannot audit that decision.
